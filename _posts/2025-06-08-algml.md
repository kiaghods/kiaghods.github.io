## Algebra Crash Course

### Groups

A group is a set of elements, $G$, equipped with a binary operation, $\circ$, that combines any two elements to form a third. For $(G, \circ)$ to be a group, it must satisfy the below axioms: 
1. **Closure**: $\forall g_{1}, g_{2} \in G$, $g_{1} \circ g_{2} \in G$
2. **Composition is associative**: $\forall g_{1}, g_{2}, g_{3} \in G$, $(g_{1} \circ g_{2}) \circ g_{3} = g_{1} \circ (g_{2} \circ g_{3})$. 
3. **There is an identity element**: $\exists e \in G$ such that $\forall g \in G$, $e \circ g = g \circ e = g$. 
4. **Every element has an inverse**: $\forall g \in G$, $\exists h \in G$ such that $g \circ h = h \circ g = e$. 

A primary example relevant to neural networks is the translation group, which describes shifting objects without rotation. For instance, the set of all integer translations on a 2D grid, $\mathbb{Z}^2$, forms a group under vector addition.[^1]

### Group Actions

A group becomes useful when it acts upon some data. Let $X$ be the set representing our data space (e.g., the space of all possible images). We say that a group $G$ _acts on_ $X$ if there is a function $\phi : G \times X \to X$ which maps an element of the group $g \in G$ and a data point $x \in X$ to a (potentially different) data point; that is, $(g, x) \mapsto g \cdot x$. This action must be consistent with the group structure. Formally, a group action satisfies the following axioms: 
1. **Identity**: $e \cdot x = x$ for all $x \in X$, and 
2. **Compatibility**: $h \cdot (g \cdot x) = (h \circ g) \cdot x$ for all $g, h \in G$ and all $x \in X$. 


## Equivariance and Invariance
With these definitions, we can now state precisely what it means for a function, such as a neural network layer, to respect symmetry.
### Formal Definition of Equivariance

Let $\mathcal{F} : X \to Y$ be a function that maps from an input data space $X$ to an output space $Y$ (e.g., a feature map). Assume a group $G$ acts on both $X$ and $Y$. We say that $\mathcal{F}$ is **equivariant** to the action of $G$ if transforming the input and then applying the function yields the same result as applying the function first and then transforming the output. 

Formally, $\mathcal{F}$ is equivariant if:

$$
\mathcal{F} (g \cdot x) = g \cdot \mathcal{F}(x) \quad \forall g\in G, x \in X
$$

In practice, this property is crucial for intermediate layers of a network, as it ensures that geometric or structural information is preserved and processed consistently across the data space.

### Formal Definition of Invariance
Invariance is a specific case of equivariance. A function $\mathcal{F}: X \to Y$ is **invariant** if its output is completely insensitive to transformations of the input by the group $G$. 

Formally, $\mathcal{F}$ is invariant if: 

$$
\mathcal{F}(g \cdot x) = \mathcal{F}(x) \quad \forall g \in G, x \in X
$$

In general, this is the desired property for a final classification output. The label of an object should not change, for example, just because the object has been shifted in the image.

## Convolutional Neural Networks
Briefly, I begin this section by describing Convolutional Neural Networks (CNNs) and then further describe their relation to some of the aforementioned desired algebraic properties. 

From the start: CNNs are a class of neural networks that have become the de facto standard for computer vision tasks. Their architecture is specifically designed to process data with a grid-like topology, such as an image. The core building block of a CNN is the convolution layer. Contrasting with traditional neural networks which consist of dense connections, a convolution layer uses a set of learnable filters, or kernels. Each filter is a small matrix of weights that slides -- or convolves -- across the input image, detecting specific local features like edges, corners, or textures. As the filter moves, it produces a feature map that highlights where these patterns occur in the image. This is typically followed by a pooling layer, such as max-pooling, which downsamples the feature map to make the representation more manageable and robust. 

The reason this architecture is so remarkably effective brings us back to the principles of symmetry. The convolution operation, with its sliding filter and shared weights, is a direct, practical implementation of translational **equivariance**. Because the same filter is applied across all spatial locations, if an object in the input image shifts, its representation in the feature map will shift by the same amount. Indeed, this is a realization of the formal relationship $\mathcal{F}(g \cdot x) = g \cdot \mathcal{F}(x)$. The Python code below demonstrates this principle; when the input square is shifted, the output from the convolutional layer is identically shifted. 

An important caveat is that for a final classification, it is not just equivariance we desire, but **invariance**; that is, the label should not change if the object's position does. The pooling layer contributes to this goal. By summarizing a local neighborhood with a single value (e.g., the maximum), the network becomes less sensitive to the precise location of features. This process of composing equivariant convolutional layers with locally invariant pooling layers allows the network to build a representation that is both rich in features and robust to their exact spatial location. 


```python
import torch
import torch.nn as nn
import matplotlib.pyplot as plt

# single-channel 7x7 image with a square in the middle
img = torch.zeros(1, 1, 7, 7)
img[0, 0, 2:5, 2:5] = 1.0  # center square

# Shifted version of the same image (1 pixel right)
img_shifted = torch.zeros_like(img)
img_shifted[0, 0, 2:5, 3:6] = 1.0  # right-shifted square

# convolutional layer with fixed weights (edge detector)
conv = nn.Conv2d(1, 1, kernel_size=3, bias=False)
with torch.no_grad():
    conv.weight[:] = torch.tensor([[[[1, 0, -1], 
                                     [1, 0, -1], 
                                     [1, 0, -1]]]])  # Sobel-like edge detector

# outputs
out1 = conv(img).squeeze().detach().numpy()
out2 = conv(img_shifted).squeeze().detach().numpy()

# figure of the images before and after the conv layer
fig, axs = plt.subplots(1, 2, figsize=(10, 4))
axs[0].imshow(img.squeeze().detach().numpy(), cmap='gray')
axs[0].set_title('Original Image')
axs[1].imshow(img_shifted.squeeze().detach().numpy(), cmap='gray')
axs[1].set_title('Shifted Image')
plt.tight_layout()
plt.show()

fig, axs = plt.subplots(1, 2, figsize=(10, 4))
axs[0].imshow(out1, cmap='gray')
axs[0].set_title('Original Image Output')
axs[1].imshow(out2, cmap='gray')
axs[1].set_title('Shifted Image Output')
plt.tight_layout()
plt.show()
```

### The Role of Pooling
To see how pooling builds invariance, we can manually create two feature maps. The first has a feature in one location. The second has the same feature shifted slightly, but still within the same local neighborhood that the pooling layer will consider.

As the code below shows, even though the inputs to the pooling layer are different, the final outputs become identical. This demonstrates the layer's insensitivity to the feature's precise location.

```python 
feature_map1 = torch.zeros(1, 1, 4, 4)
feature_map1[0, 0, 1, 1] = 10.0 # Feature at position (1, 1)

feature_map2 = torch.zeros(1, 1, 4, 4)
feature_map2[0, 0, 0, 1] = 10.0 # Feature shifted to (0, 1)

# Both (1,1) and (0,1) fall within the same top-left 2x2 pooling window.

# Define a max-pooling layer with a 2x2 window
pool = nn.MaxPool2d(kernel_size=2, stride=2)

# Apply pooling to both feature maps
pooled_out1 = pool(feature_map1).squeeze().detach()
pooled_out2 = pool(feature_map2).squeeze().detach()

# Visualize the inputs and pooled outputs
fig, axs = plt.subplots(2, 2, figsize=(8, 8))
axs[0, 0].imshow(feature_map1.squeeze(), cmap='gray', vmin=0, vmax=10)
axs[0, 0].set_title('Input 1 to Pool')
axs[0, 1].imshow(feature_map2.squeeze(), cmap='gray', vmin=0, vmax=10)
axs[0, 1].set_title('Input 2 to Pool (Shifted)')
axs[1, 0].imshow(pooled_out1, cmap='gray', vmin=0, vmax=10)
axs[1, 0].set_title('Pooled Output 1')
axs[1, 1].imshow(pooled_out2, cmap='gray', vmin=0, vmax=10)
axs[1, 1].set_title('Pooled Output 2')
plt.tight_layout()
plt.show()
```

## Broadening the Scope
The principles of symmetry and equivariance are not confined to the translational symmetry of images. In fact, they form a foundational design pattern across many of modern deep learning's most powerful architectures.
* **Graph Neural Networks (GNNs)**: Graphs possess a different kind of symmetry: **permutation symmetry**. The structure of a graph is defined by its nodes and their connections, not by the arbitrary order in which they might be listed in an adjacency matrix. GNNs are designed to respect this by using a message-passing mechanism, where a node's representation is updated by aggregating information from its neighbors. This aggregation is order-independent, making the GNN permutation equivariant. If you permute the nodes in the input, the output node embeddings are simply permuted in the exact same way.
* **Transformers**: The self-attention mechanism at the heart of the Transformer architecture is also fundamentally permutation equivariant. It treats the input sequence as a set of tokens, evaluating the interaction of every token with every other token, irrespective of their initial positions. This is precisely why positional encodings must be explicitly added to the input embeddings. Without them, the Transformer would be unable to distinguish between "the cat sat on the mat" and "the mat sat on the cat." This provides a fascinating contrast to CNNs, where geometric structure is a built-in feature rather than an additive one.

## Conclusion - The Power of Inductive Bias
We began with the formal, abstract language of group theory and arrived at the practical success of modern neural networks. The connection is a profound one: the most effective architectures are often those that intentionally embody the intrinsic symmetries of their data.

By building models like CNNs to be equivariant to translation, we provide them with a powerful **inductive bias**. The model does not need to waste its learning capacity discovering the fundamental rule that an object's identity is independent of its location; this knowledge is hard-coded into its architecture. This has two critical benefits: (1) **Data Efficiency**, that is the model can learn from far fewer examples because it automatically generalizes its knowledge across all possible translated positions; and (2) **Better Generalization**, that is the model is more robust and performs better on unseen data because it is founded on a more fundamental understanding of the data's structure.

These ideas -- of identifying the underlying symmetry of a domain and constructing equivariant models -- are the cornerstone of **Geometric Deep Learning**. This approach suggests the path to more capable AI may lie not just in bigger datasets, but in building models that perceive the world through the elegant and powerful lens of symmetry.
